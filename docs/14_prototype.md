# 장봄 프로토타입 — 자주 사는 상품 다시 주문하기

> **요약:** 홈의 "지난번 주문 그대로 담기 ›"에서 시작해 장바구니와 결제를 거쳐 주문 완료까지 가는 다시 주문하기 흐름의 인터랙션 명세다. 예외 상황으로 '마감 시간이 지났을 때'와 '지난 주문 상품 중 품절이 있을 때'를 함께 정리했다.

## 배경

- **근거 파일:** `flow.png`, `10_screens.md`
- **참고:** `flow.png`에는 다시 주문하기 경로가 따로 없다. 다시 주문하기의 입구는 `10_screens.md`의 홈 '자주 사는 상품 영역'과 "지난번 주문 그대로 담기 ›" 버튼에만 있다.
- **표기 원칙:** 근거가 없는 판단은 ⚠️ **가정**으로 표시한다.

## 2. 예외 상황

### 예외 1 — 마감 시간이 지났을 때

| # | 화면 | 누르는 곳 | 누른 뒤 일어나는 일 (이동/상태 변경) | 사용자에게 보이는 문구 |
|---|---|---|---|---|
| E1-1 | 홈 | (앱 열기, 마감 이후) | 도착 안내에 불가 이유와 다음 가능 시각을 보여 준다. 지난 주문 안내에서도 '확정' 표현을 뺀다. ⚠️ **가정** | "오늘 마감(○시)이 지났어요 · ○일 아침 도착" |
| E1-2 | 홈 | "지난번 주문 그대로 담기 ›" | 그대로 담고 장바구니로 이동한다. 도착 안내에 다음 가능 시각을 보여 준다. ⚠️ **가정** | "마감이 지나 ○일 아침에 도착해요" |
| E1-3 | 장바구니 | 결제하기 버튼 (마감 지남) | 결제 화면으로 이동하고 도착 시각을 다음 가능 시각으로 바꿔 보여 준다. flow의 '마감이 지났나요? → 예 · 다음 도착 받기'에 해당한다. | (결제) 도착 시각 "○일 아침 7시 전" |
| E1-4 | 장바구니 | (장바구니에 머무는 동안 마감이 지남) | 도착 안내와 배지를 다시 계산하고 결제하기 버튼 문구를 갱신한다. ⚠️ **가정** | "방금 마감이 지났어요 · ○일 아침 도착으로 바뀌었어요" ⚠️ **가정** |

### 예외 2 — 지난 주문 상품 중 품절이 있을 때

| # | 화면 | 누르는 곳 | 누른 뒤 일어나는 일 (이동/상태 변경) | 사용자에게 보이는 문구 |
|---|---|---|---|---|
| E2-1 | 홈 | (진입) | 지난 주문 안내에 품절 개수를 미리 표시한다. ⚠️ **가정** | "○/○ 주문 · ○개 · 1개 품절" ⚠️ **가정** |
| E2-2 | 홈 | "지난번 주문 그대로 담기 ›" | 주문 가능한 상품만 담고 장바구니로 이동한다. 품절 상품은 맨 위로 모으고 빠지는 상품 안내와 빠지는 상품 카드에 표시하며, 합계에서 뺀다. | "○○ 1개는 이번 주문에서 빠져요" / "빠지는 상품 · ○○ ○원" |
| E2-3 | 장바구니 | "이걸로 바꾸기" (대체 상품) | 원래 상품을 대체 상품으로 바꾸고 장바구니에 머문다. 대체 상품은 내일 아침 도착 목록으로 옮겨지고, 빠지는 상품 안내가 사라지며 금액이 갱신된다. 자동 대체는 하지 않는다. | 제목 "대신 이 상품 어때요?" → "○○를 뺐어요 · 되돌리기" |
| E2-4 | 장바구니 | 되돌리기 | 바꾸기 전 상태로 돌아가고 장바구니에 머문다. | "○○ 1개는 이번 주문에서 빠져요" |
| E2-5 | 결제 | 결제하기 버튼 (직전에 품절 발생) | 해당 상품만 빼고 진행할지, 장바구니로 돌아갈지 고르게 한다. 담은 장바구니는 사라지지 않는다. | "방금 ○○이 품절됐어요" · [빼고 결제하기] · [장바구니로] ⚠️ **가정** (문구) |

| 최근 산 상품 카드의 담기 | 1개 담고 홈에 머문다 | `10_screens.md`에서 영역 자체가 가정 |
| 주문 완료 후 '지난 주문' 저장 | 이번 주문을 다음 다시 주문하기의 기준으로 쓴다 | 근거 없음 |
| 담기 완료 토스트 · 마감 중 갱신 · 결제 직전 품절 문구 | 시안용 문구 | 근거 없음 |
