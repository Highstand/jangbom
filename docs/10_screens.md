# 장봄 화면 명세 — 「도착 먼저」 MVP

> **요약:** 플로우의 화면 5개(홈 · 주소 확인·변경 · 검색 결과 · 장바구니 · 결제)를 목적, 구성 요소, 상태, 이동으로 정리했다. 모든 화면은 '담기 전에 내 주소로 내일 아침 도착이 되는지 안다'(H1-1)를 지키는 데 맞췄다.

## 0. 공통 요소 이름

여러 화면에 반복되는 요소는 아래 이름으로 통일한다.

| 이름 | 무엇 | 쓰는 화면 |
|---|---|---|
| 도착 안내 | 저장된 주소 기준 내일 아침 도착 가능 여부와 마감 시각 한 줄 | 홈, 장바구니 |
| 도착 배지 | 상품마다 붙는 '내일 아침 확정' 또는 '내일 아침 불가' 표시. 같은 상품은 어느 화면에서나 같은 배지를 보여 준다 | 검색 결과, 장바구니 |
| 상품 카드 | 상품 이름 · 용량 · 가격 · 도착 배지 · 담기 버튼 묶음 | 검색 결과, 장바구니 |
| 담기 버튼 | 상품을 장바구니에 넣는 버튼 | 검색 결과 |
| 대체 상품 | 품절·불가 상품 대신 제안하는 같은 품목의 상품 카드. 제목은 어느 화면에서나 "대신 이 상품 어때요?" | 검색 결과, 장바구니 |
| 바꾸기 버튼 | 장바구니에서 원래 상품을 대체 상품으로 바꾸는 버튼 "이걸로 바꾸기" | 장바구니 |
| 주소 바꾸기 버튼 | 주소 확인·변경 바텀시트를 여는 버튼 | 홈, 결제 |
| 검색창 | 품목 검색 입력 칸 | 홈, 검색 결과, 장바구니 |
| 결제하기 버튼 | 다음 단계(결제)로 넘어가는 주 버튼 | 장바구니, 결제 |

## 1. 홈

| 항목 | 내용 |
|---|---|
| 목적 | 앱을 여는 순간, 담기 전에 내 주소로 내일 아침 도착이 되는지와 마감 시각을 알려 준다. |

**구성 요소 (위에서 아래)**

| 순서 | 요소 | 설명 |
|---|---|---|
| 1 | 도착 안내 | "내 주소로 내일 아침 도착 가능 · 마감 ○시" 첫 줄 |
| 2 | 주소 바꾸기 버튼 | 도착 안내 옆, 현재 주소 일부 표시 |
| 3 | 검색창 | 한 손으로 바로 누르는 위치 |
| 4 | 자주 사는 상품 영역 | 제목 옆에 "지난번 주문 그대로 담기 ›" 버튼, 제목 아래에 지난 주문 안내 한 줄("○/○ 주문 · ○개 · 모두 내일 아침 확정")을 둔다. 그 아래 최근 산 상품 카드(구매 횟수 표시) ⚠️ **가정** |
| 5 | 장바구니 진입 | 담은 개수 표시 |

**상태**

| 상태 | 보여 줄 것 |
|---|---|
| 빈 상태 | 저장된 주소가 없음 → 도착 안내 자리에 "주소를 넣으면 내일 아침 도착 여부를 알려 드려요"와 주소 바꾸기 버튼 |
| 로딩 | 도착 안내 자리만 자리표시로 두고, 검색창은 바로 쓸 수 있게 둔다 |
| 오류 | 도착 여부를 못 불러옴 → "도착 정보를 확인하지 못했어요"와 다시 시도. 확정처럼 보이는 문구는 쓰지 않는다 |
| 품절 | 해당 없음. 도착 불가일 때는 이유(마감 지남 · 배송 불가 지역)와 다음 가능 시각을 도착 안내에 표시 |

**이동**

| 누르는 것 | 가는 곳 |
|---|---|
| 주소 바꾸기 버튼 | 2. 주소 확인·변경 |
| 검색창 (품목 검색) | 3. 검색 결과 |
| 지난번 주문 그대로 담기 | 지난 주문 상품을 담고 4. 장바구니 ⚠️ **가정** |
| 장바구니 진입 | 4. 장바구니 |

## 2. 주소 확인·변경 (바텀시트)

| 항목 | 내용 |
|---|---|
| 목적 | 도착 안내의 기준이 되는 주소가 맞는지 확인하고, 필요하면 바꾼다. |

**구성 요소 (위에서 아래)**

| 순서 | 요소 | 설명 |
|---|---|---|
| 1 | 제목 | "도착 기준 주소" |
| 2 | 현재 주소 | 선택된 주소 표시 |
| 3 | 저장된 주소 목록 | 집 · 회사 등, 하나만 선택 |
| 4 | 새 주소 입력 | 주소 검색 진입 |
| 5 | 주소 저장 버튼 | 저장 즉시 도착 안내를 다시 계산 |

**상태**

| 상태 | 보여 줄 것 |
|---|---|
| 빈 상태 | 저장된 주소 없음 → 목록 대신 새 주소 입력만 보여 줌 |
| 로딩 | 저장 후 도착 여부 재확인 중 표시, 주소 저장 버튼 비활성 |
| 오류 | 주소 저장 실패 → 시트를 닫지 않고 다시 시도 안내 |
| 품절 | 해당 없음. 새벽배송 불가 지역이면 저장 전에 "이 주소는 내일 아침 도착이 안 돼요"를 미리 알림 |

**이동**

| 누르는 것 | 가는 곳 |
|---|---|
| 주소 저장 버튼 | 1. 홈 (도착 안내 갱신). 결제에서 열었으면 5. 결제로 복귀 |
| 바깥 영역 · 닫기 | 열었던 화면으로 복귀, 변경 없음 |

## 3. 검색 결과

| 항목 | 내용 |
|---|---|
| 목적 | 품목을 찾으면서 상품마다 내일 아침 오는지를 담기 전에 알게 한다. |

**구성 요소 (위에서 아래)**

| 순서 | 요소 | 설명 |
|---|---|---|
| 1 | 검색창 | 입력한 품목 유지 |
| 2 | 결과 개수 | "○개 중 ○개 내일 아침 도착" |
| 3 | 상품 카드 목록 | 상품 카드마다 도착 배지와 담기 버튼. 내일 아침 불가 상품도 '내일 아침 불가' 배지로 담기 전에 보여 줌 |
| 4 | 대체 상품 | 품절 상품 카드 아래에 "대신 이 상품 어때요?" 제목과 함께 붙임 |
| 5 | 장바구니 진입 | 담은 개수 표시 |

**상태**

| 상태 | 보여 줄 것 |
|---|---|
| 빈 상태 | 결과 없음 → "찾는 상품이 없어요"와 검색어 고치기 안내 |
| 로딩 | 상품 카드 자리표시. 도착 배지가 늦게 오면 배지 자리만 비워 두고 '확정'으로 먼저 보이지 않게 함 |
| 오류 | 결과를 못 불러옴 → 다시 시도. 도착 배지만 실패하면 "도착 확인 중"으로 표시 |
| 품절 | 담기 버튼 대신 "품절"과 대체 상품 제안 |

**이동**

| 누르는 것 | 가는 곳 |
|---|---|
| 담기 버튼 (품절 아님) | 장바구니에 담고 이 화면에 머묾 → 4. 장바구니에서 확인 |
| 대체 상품의 담기 버튼 (품절일 때) | 대체 상품을 담고 이 화면에 머묾 |
| 장바구니 진입 | 4. 장바구니 |

## 4. 장바구니

| 항목 | 내용 |
|---|---|
| 목적 | 결제 전에 담은 상품이 모두 내일 아침 오는지 한 번에 확인하게 한다. 결제 화면에서 놀라는 일을 없애는 마지막 지점이다. |

**구성 요소 (위에서 아래)**

| 순서 | 요소 | 설명 |
|---|---|---|
| 1 | 도착 안내 | 마감 시각 · 남은 시간 · 주소 기준 |
| 2 | 빠지는 상품 안내 | 불가 상품이 있을 때만. "○○ ○개는 이번 주문에서 빠져요"와 이유(예: 이 상품만 ○○:○○ 마감이 지났어요) |
| 3 | 불가 · 품절 상품 카드 | 맨 위로 모음. 도착 배지 · 빼기 |
| 4 | 대체 상품 | "대신 이 상품 어때요?" 제목과 바꾸기 버튼("이걸로 바꾸기") |
| 5 | 내일 아침 도착 상품 목록 | "내일 아침 도착 ○개" 제목, 상품 카드마다 도착 배지 · 수량 · 빼기 |
| 6 | 다음 품목 검색 | 검색창으로 이어지는 진입 |
| 7 | 빠지는 상품 카드 | 불가 상품이 있을 때만. "빠지는 상품 · 상품명 금액" 한 줄 |
| 8 | 금액 요약 | 상품 금액 · 배송비 · 합계. 빠지는 상품은 합계에 넣지 않음 |
| 9 | 결제하기 버튼 | "○개 ○원 결제하기" (실제 주문되는 개수와 금액) |

**상태**

| 상태 | 보여 줄 것 |
|---|---|
| 빈 상태 | 담은 상품 없음 → "아직 담은 게 없어요"와 검색창 진입, 결제하기 버튼 비활성 |
| 로딩 | 도착 요약 자리표시, 결제하기 버튼 비활성 |
| 오류 | 도착 요약을 못 불러옴 → "도착 확인 실패"와 다시 시도. 확인 전엔 결제하기 버튼 비활성 ⚠️ **가정** |
| 품절 · 불가 | 해당 상품은 맨 위로 모으고 빠지는 상품 안내 · 빠지는 상품 카드에 표시. 대체 상품 제안 |
| 바꾼 뒤 | 원래 상품 자리에 "○○를 뺐어요 · 되돌리기", 대체 상품은 수량 조절로 바뀌어 내일 아침 도착 목록에 들어감. 빠지는 상품 안내·카드는 사라지고 금액과 결제하기 버튼이 갱신됨 |

**이동**

| 누르는 것 | 가는 곳 |
|---|---|
| 바꾸기 버튼 (이걸로 바꾸기) | 원래 상품을 대체 상품으로 바꾸고 이 화면에 머묾 (바꾼 뒤 상태) |
| 되돌리기 | 바꾸기 전 상태로 돌아가고 이 화면에 머묾 |
| 다음 품목 검색 | 3. 검색 결과 |
| 결제하기 버튼 (마감 전) | 5. 결제 |
| 결제하기 버튼 (마감 지남) | 5. 결제, 도착 시각을 다음 가능 시각으로 바꿔 보여 줌 |

## 5. 결제

| 항목 | 내용 |
|---|---|
| 목적 | 배송지와 도착 시각을 마지막으로 확인하고 주문을 끝낸다. 새로운 사실을 처음 알리는 화면이 아니라 확인만 하는 화면이다. |

**구성 요소 (위에서 아래)**

| 순서 | 요소 | 설명 |
|---|---|---|
| 1 | 배송지 | 주소 바꾸기 버튼 포함 |
| 2 | 도착 시각 | "내일 아침 7시 전" 또는 다음 가능 시각 |
| 3 | 주문 상품 요약 | 개수 · 금액 |
| 4 | 결제 수단 | 저장된 수단 |
| 5 | 결제하기 버튼 | 최종 금액과 함께 |

**상태**

| 상태 | 보여 줄 것 |
|---|---|
| 빈 상태 | 결제 수단 없음 → 결제 수단 추가 안내, 결제하기 버튼 비활성 |
| 로딩 | 결제 처리 중, 결제하기 버튼 중복 누름 막음 |
| 오류 | 결제 실패 → 장바구니를 그대로 두고 다시 시도. 담은 장이 사라지지 않게 함 |
| 품절 | 결제 직전에 품절 발생 → 해당 상품만 빼고 진행할지, 4. 장바구니로 돌아갈지 고르게 함 |

**이동**

| 누르는 것 | 가는 곳 |
|---|---|
| 주소 바꾸기 버튼 | 2. 주소 확인·변경 → 저장 후 도착 시각 갱신하고 복귀 |
| 결제하기 버튼 | 주문 완료 |
| 뒤로 | 4. 장바구니 |

## 아직 가정인 것

- ⚠️ **가정** 홈의 '자주 사는 상품 영역'은 원탭 재주문이 MVP에서 빠져 있어, 처음엔 최근 산 상품 카드와 '지난번 주문 그대로 담기' 버튼 수준으로 둔다. 버튼을 누른 뒤 바로 장바구니로 갈지, 홈에 머물지는 정하지 않았다.
- ⚠️ **가정** 도착 정보를 확인하지 못한 동안 결제하기 버튼을 막는 것이 주문 포기를 늘리지 않는지는 시안 테스트로 확인해야 한다.
- ⚠️ **가정** 플로우의 '예 · 대체 담기'는 품절 상품을 사용자가 고른 대체 상품으로 바꾸는 것으로 해석했고, 자동 대체는 넣지 않았다.
- ⚠️ **가정** 지난 주문 안내의 날짜, 빠지는 상품 안내의 마감 시각은 시안용 값이다.

## 수정 기록

| 번호 | 고친 것 | 이유 |
|---|---|---|
| 1 | 홈 자주 사는 상품 영역에 "지난번 주문 그대로 담기 ›" 버튼과 지난 주문 안내 한 줄을 넣었다 | '지난번 장바구니'가 무엇을 담는지 모호해 다시 주문하기의 첫 입구에서 검색으로 돌아가게 했다 (A님 L09~10, B님 L27) |
| 2 | 장바구니에 빠지는 상품 안내·카드를 넣고 결제하기 버튼에 실제 개수·금액을 쓰며, 같은 상품의 도착 배지를 화면끼리 맞췄다 | 불가 상품이 합계에서 말없이 빠져 결제 직전에 다시 놀라는 일이 생겼다 (A님 L19~20, B님 L16) |
| 3 | 대체 상품 버튼을 "이걸로 바꾸기"로 바꾸고 바꾼 뒤 상태(뺐어요 · 되돌리기)를 더했으며 제목을 "대신 이 상품 어때요?"로 통일했다 | '담기'가 바꾸기인지 더하기인지 몰라 장바구니 정리 단계에서 중복 구매와 재확인을 만들었다 (B님 L07, L11) |
