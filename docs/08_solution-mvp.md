# 08. 장봄 솔루션 아이디어와 MVP

> **요약:** 선정 HMW(H1-1)에 답하는 아이디어를 11개로 정리해 점수를 매기고, 1위 '홈 내 주소 도착 안내'와 3위 '상품 단위 도착 표시'를 묶은 콘셉트 「도착 먼저」를 골라 화면 4개짜리 MVP로 범위를 정했다.

## 배경

- **목적:** `07_problem.md`의 선정 HMW에 답하는 솔루션을 내고, 처음 만들 범위를 정한다.
- **선정 HMW:** 어떻게 하면 담기 시작하기 전에 내 주소로 내일 아침 도착이 되는지 알게 할 수 있을까? (H1-1)
- **페르소나:** `05_persona.md`의 김한결 (반복 구매형)
- **근거 파일:** `07_problem.md`, `06_journey-map.md`, `05_persona.md`, `03_pain-points.md`, `02_competitors.md`, `01_ideas.md`, `interview-A.md`, `interview-B.md`, `interview-C.md`
- **표기 원칙:** 발화는 인터뷰 녹취의 줄 번호(예: A님 L30)로 적는다. 근거가 없는 판단은 ⚠️ **가정**으로 표시한다.
- **보드:** [콘셉트 카드 · 도착 먼저](https://www.figma.com/board/lURA1jafjxVvI4avmhrgA0/?node-id=105-1025)

## 1. 솔루션 아이디어와 평가

아이디어 15개를 내고 비슷한 것을 합쳐 11개로 평가했다. 기준은 1~5점(높을수록 좋음)이고, 합계가 같으면 HMW 해결 점수가 높은 쪽을 앞에 둔다(`01_ideas.md` 동점 규칙과 같은 방식).

★ = `02_competitors.md`의 빈자리(오른쪽 위, '1인분 소량 구매력 높음 × 다시 담기 쉬움')를 채우는 아이디어

### 합친 아이디어

| 합친 아이디어 | 합친 내용 |
|---|---|
| 홈 '내 주소 도착 안내' | 홈 첫 줄 도착 확인 + 도착 불가 즉시 안내 |
| 상품 단위 도착 표시 | 상품 카드 도착 배지 + 검색 결과 도착 우선 정렬 |
| 재주문 도착 확정 카드 | 재주문 카드 도착 확정 + 재주문 전 도착 불가 상품 분리 |
| 장바구니 도착 요약·마감 경고 | 장바구니 도착 요약 + 마감 이른 상품 경고 |

### 평가에서 보인 것

- 1·3·4위는 같은 데이터(주소·상품별 도착 확정·마감)를 화면 위치만 달리해 쓴다. 그래서 하나의 콘셉트로 묶었다.
- ★ 2개 중 재주문 도착 확정 카드(2위)는 상위권이고, 1인분 필터(8위)는 선정 HMW와 거리가 멀어 낮았다.
- 7·10·11위는 나쁜 아이디어라서가 아니라 선정 HMW와 다른 문제를 다뤄 점수가 낮다.

## 2. 선정 콘셉트: 도착 먼저

| 항목 | 내용 |
|---|---|
| 묶은 아이디어 | 홈 '내 주소 도착 안내'(1위) + 상품 단위 도착 표시(3위) |
| 한 줄 설명 | 앱을 여는 순간 내 주소로 내일 아침 오는지 알려 주고, 담는 상품마다 그 약속이 지켜지는지 보여 준다. |
| 핵심 가치 | 결제 직전에 마감·배송 불가를 처음 알게 되는 일(`06_journey-map.md` 4단계, -2)을 없앤다. |
| 이름의 뜻 | 담기 전에 도착부터 알려 준다는 순서를 그대로 이름에 담았다. |

## 3. MVP 기능과 뺀 기능

기준: 핵심 가치를 확인하는 데 없으면 안 되는가

| 기능 | 필수/나중 | 이유 |
|---|---|---|
| 홈 첫 줄 도착 안내 (저장된 주소 기준 도착 가능 여부·마감 시각) | **필수** | HMW에 바로 답하는 콘셉트의 중심이다. 이게 없으면 '담기 전에 안다'를 확인할 수 없다. (B님 L16) |
| 도착 불가일 때 이유와 다음 가능 시각 안내 | **필수** | B님이 겪은 '이 시간 지나면 우리 동네는 안 됨'(L15)을 담기 전에 알린다. 안 될 때를 빼면 핵심 가치의 절반만 확인한다. |
| 홈 안내에서 주소 확인·변경 | **필수** | 답이 주소에 달려 있어, 주소가 틀리면 안내 전체가 틀린다. ⚠️ **가정** |
| 상품 카드 도착 배지 (내일 아침 확정 / 불가) | **필수** | 주소는 되는데 특정 상품만 안 되는 경우를 담는 순간 알린다. (리뷰 5, 13 · `01_ideas.md` 2위) |
| 장바구니 상단 도착 요약 | **필수** | 결제 화면에서 놀라는 일이 사라졌는지 확인하는 마지막 지점이다. (A님 L20) |
| 화면 위 고정 마감 바 | 나중 | 홈 안내에 마감 시각이 이미 있어, 처음엔 없어도 핵심 가치는 확인된다. |
| 검색 결과 '내일 아침 도착' 우선 정렬 | 나중 | 배지만으로도 구분은 된다. 정렬 규칙은 사용 데이터를 본 뒤 정한다. |
| 상품별 마감 시각 경고 | 나중 | A님 한 명 경험(L19)이고 `07_problem.md`에서 '노력 큼'(H1-2)이었다. 처음엔 배지의 확정/불가로 대신한다. |
| 재주문 카드에 도착 확정 표시 | 나중 | 원탭 재주문이 먼저 있어야 붙일 수 있다. |
| 퇴근 시각 맞춤 리마인드 | 나중 | 앱을 열게 하는 기능이라 '열었을 때 아는가'라는 핵심 가치와 별개다. |
| 공동현관 출입 정보 저장 | 나중 | 배송 실패 예방이라 선정 HMW 밖이다. 주소 확인 화면에 나중에 붙이기 쉽다. |
| 입고일·도착 신뢰 표시·배송 시간대 미리보기 | 나중 | 신선도·정시 도착·선택지 문제로, 선정 HMW와 다른 문제다. |

### MVP 화면 (4개)

| 번호 | 화면 | 필수 기능 |
|---|---|---|
| 1 | 홈 | 도착 안내, 도착 불가 안내 |
| 2 | 주소 확인·변경 (바텀시트) | 주소 확인·변경 |
| 3 | 검색 결과·상품 목록 | 상품 카드 도착 배지 |
| 4 | 장바구니 | 도착 요약 |

## 4. 아직 가정인 것

아래는 확인 전인 가정이다. 추가 인터뷰, 개발 검토, 시안 테스트로 검증이 필요하다.

- ⚠️ **가정** 아이디어 점수는 디자이너 판단이고, 팀 합의나 개발 검토를 거치지 않았다.
- ⚠️ **가정** 필수 기능 전부와 실현 가능성 점수 대부분은 상품별 재고와 배송 권역 데이터를 실시간으로 받을 수 있다는 `01_ideas.md`의 가정에 달려 있다.
- ⚠️ **가정** 밤 11시 마감, 아침 7시 전 도착은 `01_ideas.md`의 시안용 임시 값이다.
- ⚠️ **가정** 주소 확인·변경이 필수인 이유(회사 등 다른 주소로 받는 사람)는 인터뷰에서 확인하지 않았다.
- ⚠️ **가정** 다음 날 아침 장면에서는 필수 기능의 화면을 직접 쓰지 않는다. 전날 확인한 약속이 지켜지는지가 이 콘셉트의 신뢰를 정한다고 보고 넣었다.
- ⚠️ **가정** 상품별 마감 경고를 빼면 A님 L19처럼 상품 하나만 마감이 이른 경우는 배지의 '불가'로만 알 수 있다. 이게 충분한지는 시험해 봐야 한다.
- ⚠️ **가정** 재주문 도착 확정 카드의 실현 점수는 원탭 재주문과 도착 보장 배지를 결합하는 난이도를 따로 검토하지 않은 값이다.
- ⚠️ **가정** 공동현관 거주 비율, 모바일 웹 푸시 지원, 낮 배송 운영 여부는 확인하지 않았다.
- ⚠️ **가정** `02_competitors.md`는 경쟁 앱이 마감을 어느 화면에서 보여 주는지 확인하지 않았다. 그래서 도착을 미리 보여 주는 아이디어만으로는 빈자리 표시(★)를 하지 않았다.
- ⚠️ **가정** C님은 대표 페르소나 밖의 사용자라 보조 근거로만 썼다.
- ⚠️ **가정** 인터뷰 3명과 리뷰 30개는 모두 가상 데이터다.
